قرارداد hash در payload نسخه‌دار است و از JSON canonical با ترتیب مجموعه‌های

انسانی جعل یا صادر نمی‌کند و بازنویسی hash جای مرور واقعی را نمی‌گیرد.

### Hands-on

مهارت ticket-walkthrough پس از checks و review در همین جلسه اعمال شد. راهنما:
`.scratch/infrastructure-corrective-review/acceptance/01-corrections/guide.md`.
`prepare.py` فقط fixtureهای مصنوعی موجود را بیرون مخزن کپی می‌کند؛ نه فصل واقعی
و نه فایل رسمی منبع را ایجاد یا منتشر نمی‌کند. CLI واقعی در sandbox موقت اجرا شد:
check اولیه، hash نسخه، رد تأیید پس از تغییر geography، بازگشت به review، رد
انتشار دوباره با hash قدیمی، بازیابی مصنوعی برای نمایش قرارداد، رد evidence
تازه، ثبات hash پس از تغییر نمایشی، رد force-add و حفظ فایل محلی پس از cached
removal، و دو generate یکسان، همه مطابق انتظار بودند. فرمان‌های دقیق S2 تا S6
از Markdown راهنما نیز اجرا و با exit مورد انتظار تأیید شدند؛ sandbox preflight
پاک شد و sandbox جداگانهٔ دست‌نخورده برای انسان در راهنما ثبت است.

همهٔ نتایج انسان `not_run` هستند. اقدام اول انسان:
`python3 scripts/atlas.py check` از ریشهٔ مخزن؛ انتظار PASS و یادآوری مرز اختیار
انسانی است. آماده‌بودن راهنما gate تازه‌ای برای تکمیل اصلاح یا تأیید انتشار نیست.
